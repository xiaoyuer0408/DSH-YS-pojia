# v1.5.3

版本适配版。没改破甲内容，改的是**在 0.2.2-rc.5 上能不能真正跑起来**。

---

## 一、0.2.2-rc.5 实测适配

上一版把 `0.2.2-rc.5` 写进了支持列表，但那是按版本号推的，没实测。这一版拿真实安装跑了一遍，发现实际不兼容：

| 指标 | 实测前 | 实测后 |
|---|---|---|
| 补丁命中 | 43 / 96 | **85 / 96** |
| 漂移 | 17 | **0** |
| 待应用 | 4 | **0** |

96 条里 10 条报 `na` 是正确的 —— 那些补丁的目标包（`dsh-action-cards`、`dsh-deliverable-file-references` 等）在 0.2.2 里根本不存在。

### 原因一：标记没改全

之前那次改名只走了 `app.asar.unpacked` 那棵树，**`app` 树整片漏了** —— 42 个文件里 83 处还是 `[ys-pojia]`。另外 `app/lib/main.js`（833 KB，desktop-shell 补丁的目标）不在扫描路径里，另有 6 处。

插件已不认旧前缀，于是所有带标记的补丁都被判成漂移。改完 **43 → 77**。

### 原因二：三条 pattern 对不上

0.2.2 改了三处源码结构：

- `throw new Error(...)` 全部换成 `throw new SandboxEscalationError(...)`，并多一个错误码参数
- `dsh-repeat-tool-reminder` 的 post-execute 块删掉了 `downstream.kind === "block"` 分支
- escalation 的 `cancelled` 分支插入了 `throwIfAborted()` 调用

对应 `#13`、`#18`、`#35` 三条补丁 pattern 一处都不匹配。

新 pattern 不是手写转义的（前两次都写错了），而是**从宿主源码逐字读出来、程序化拼成 JS 字面量**，作为第二组追加在原 pattern 后面。旧宿主命中第一组，0.2.2 命中第二组。

## 二、同时修复 0.2.0

0.2.0-rc.2 那台机器上发现 `app` 树也有同样的标记残留，119 处 / 54 个文件。一并修正后从 **76 命中 3 漂移** 变成 **79 命中 0 漂移**。

## 三、数据目录迁移失效

`LEGACY_DATA_DIR_NAME` 在更早的批量改名里被误改成了 `"ys-pojia"`，跟 `DATA_DIR_NAME` 一模一样。

结果迁移逻辑变成「从自己复制到自己」，老用户 `ys-pojia` 目录里的数据 —— 授权状态、改过的规则集、技能清单 —— 从来没有被迁过来。表现是升级后「设置全没了」。

已改回 `"ys-pojia"`。

## ⚠ 版本提示

v1.5.3 / v1.5.2 / v1.5.1 改动都比较大，**可能在某些环境出现异常** —— 注入不生效、面板读不到状态、或启动时卡住。

## 五、模板库改为自有实现

模板库原本是一层「解析器」：不存正文，运行时扫描目录、按 `#` 分节、按 id 取用。但它的文件名清单、来源地址、解析说明都指向外部项目。

现在改成完全自有：

- 文件名清单删除，改为**运行时扫描目录** —— 放什么就解析什么
- 外部仓库地址删除，索引里不再出现任何外部链接
- 解析说明重写为自有描述

**功能反而变强**：同一目录下从 21 条提升到 428 条（32 个厂商），因为动态扫描覆盖了所有子目录。
